# 德州扑克简单引擎

基于 PokerKit 的无限注德州扑克游戏，提供本地浏览器牌桌和命令行两种玩法。
默认每人 2000 筹码、盲注 10/20，无前注、无抽水，盲注不随时间上涨。

## 浏览器版：启动就能玩

使用现有的 `poker` Conda 环境：

```bash
conda activate poker
python web_app.py
```

程序会自动打开浏览器，进入 **河牌俱乐部**。也可以在项目目录运行：

```bash
./start_game.sh
```

首次入座选择“轻松练手”“认真过招”或“挑战一下”，填写昵称后点击开始。
默认是你和两位 AI，也可以选择 2–6 人桌，并在“自己挑选 AI 牌友”中自由搭配全部八种策略。
这三档是对手风格组合，并非经过评级的难度等级。

- 固定座位、图形牌桌、♠ ♥ ♦ ♣ 花色；突出当前行动者、公共牌、底池和你的底牌。
- 用按钮过牌、跟注、弃牌；滑杆或数字框调整**本轮加到**的金额，并显示还需投入多少。
- 提供最小加注和 ¼、⅓、½、⅔、¾、整个底池的快捷金额；按跟注后的底池计算加注幅度，再限制在合法范围内。点击比例只调整金额，确认“加到”后才下注。
- 全下前确认；弃牌或全下后可以快速看结果。
- AI 逐个行动，速度可调；音效默认关闭，可随时开启。打开玩法或选桌窗口、切走浏览器标签时暂停自动推进。
- 每手明确显示盈亏、主池/边池分配、未被跟注的退回金额，以及底牌和牌型对比。
- 赢得主池或边池的座位和摊牌结果显示金色 **WIN**；平分时标记所有赢家。退回未被跟注的筹码不算赢池，净盈亏仍看结算金额。
- 顶部“牌型大小”或操作区的“当前牌型”可打开图例牌型速查，从同花顺到高牌排列，并说明踢脚牌、平局和 A 的用法。
- 顶部“隐私”开关仅保存在当前浏览器：开启后自己的底牌默认为牌背，鼠标移入查看、移开隐藏；触屏按住查看，键盘可用 Tab 选中后按住空格查看。
  自己的当前牌型和结算底牌同步遮住；切走窗口、打开弹窗或开始新一手会收牌。其他设备的正常摊牌规则不受影响。
- 本休闲牌桌采用统一摊牌：所有进入摊牌的玩家都亮出底牌，包括输家；中途弃牌的玩家不亮牌。
  如果其他玩家都弃牌，结算会明确提示“无需摊牌”，即使此时公共牌已经发满五张。
- 支持连续下一手、累计战绩和最近 30 手摘要；你或其他玩家输光后会正确处理离桌及整桌结束。
- 页面刷新能恢复当前牌桌。游戏保存在本地服务器内存里，**关闭启动窗口或重启服务后不会保留牌局**。

服务只监听本机地址，默认是 `http://127.0.0.1:8765`，无须额外安装 Web 框架。
保持启动窗口运行；按 Ctrl+C 关闭。端口占用或不想自动打开浏览器时：

```bash
python web_app.py --port 8766 --no-browser
```

同一浏览器的标签页共享一桌；不同浏览器会话各自开桌。服务端验证动作和版本，
重复点击或过期页面不会重复下注。未公开的对手底牌、随机种子和牌堆不会发送给浏览器。
浏览器仅保存称呼、速度及音效偏好；全部资源来自本机。

浏览器支持 `document.modelContext` 时，会额外提供只读牌桌查询和打开选桌窗口两个可选页面工具。
普通浏览器不依赖这项功能。本次未进行浏览器交互或 WebMCP 运行时验证。

## 同一 Wi-Fi 下多人联机

只需要一台电脑运行服务器，手机、平板和其他电脑都用浏览器加入，无须安装 Python。
在服务器电脑上运行：

```bash
./start_game.sh --lan
```

等价命令：`conda run --no-capture-output -n poker python web_app.py --lan`。
如果默认端口已被其他游戏占用，可以加 `--port 8767`。
程序会输出本机的局域网地址，例如 `http://192.168.3.186:8767`，并自动打开浏览器。
请使用启动时实际显示的地址，电脑切换 Wi-Fi 或重新分配 IP 后地址可能变化。

1. 房主点击“和朋友玩”，填写昵称，选择 2–6 个座位和是否由 AI 补齐空位，再创建房间。
2. 点击“复制邀请链接”，发给同一 Wi-Fi 下的朋友。朋友打开链接、填写自己的昵称并加入。
   也可以让大家先打开同一个局域网地址，再输入六位房间码。
3. 等候室会同步显示已入座的人。每位真人点击“我准备好了”后才自动开始第一手；已准备的人可以取消准备。
4. 每台设备始终把自己的座位放在下方，只收到自己的底牌。到正式摊牌时才公开仍在比牌的玩家底牌。

可以纯真人对战，也可以真人与 AI 混坐。关掉“空位由 AI 补齐”时，两位或以上真人即可开局，
不必坐满全部座位。每手结算后，所有仍有筹码的真人都点击“准备下一手”才会继续，房主不能单独发牌。
已输光的玩家可以观战，不会阻塞下一手；如果所有真人均已输光，则由所有观众共同确认继续观看 AI。
开局后暂不支持新玩家中途加入；整桌结束后，所有房间成员同意重新组桌，才能返回等候室邀请朋友再开局。

联机牌局由服务器统一推进，大家的页面约每 0.8 秒同步一次，AI 不依赖房主浏览器。
在线思考时间为 90 秒；关闭页面或断网导致心跳中断约 12 秒后，服务器会在轮到该玩家时自动过牌或弃牌，
不会自动跟注、加注或全下。无需等满 90 秒，但页面后台被系统挂起也可能触发这个离线处理。
联机时切走标签页或打开玩法窗口不会暂停整桌。

刷新、短暂断线后，用**原设备的原浏览器、同一访问地址**返回，会恢复原座位。
同一浏览器的标签页共享身份；想在一台设备测试不同玩家，可用不同浏览器或无痕窗口。
房间顶部和操作区都有“离开牌桌”。确认后立即离桌，已开局的座位由 AI 接替；即使其他人刚刚行动，也不会因画面版本过期而无法退出。
房主展开“牌友与准备状态”，可以将其他成员移出房间；已开局时同样由 AI 接替，被移出的浏览器会收到提示。
房主离线超过 20 秒，有在线牌友时会自动转交房主；房主主动离桌则立即转交。
有成员加入、离开或被移出时，其他人的准备状态保持不变；新加入（包括主动离桌后重新加入）的玩家默认未准备。
剩余参与玩家全部准备好且满足开局人数时会自动继续；新一手或重新组桌后才统一清空准备。被移出的浏览器会话不能重新加入原房间。
输光的真人可以继续观看，整桌会持续到最后一名赢家。房间和进度仍保存在内存中，服务器关闭后不会保留。

`--lan` 会监听本机所有 IPv4 接口。普通启动方式仍仅允许本机访问。
如果其他设备打不开，请确认大家使用同一个 Wi-Fi、不是相互隔离的访客网络，并检查服务器电脑的防火墙是否允许所选 TCP 端口。
手机不能使用 `localhost` 或 `127.0.0.1` 访问另一台电脑；应使用程序显示的局域网 IP。
无需修改路由器端口转发或开放公网访问。

代码中 `browser_game.py` 负责按当前玩家生成视图，`multiplayer.py` 负责房间、身份、计时和 AI 推进，
`web_app.py` 负责 HTTP 服务。测试覆盖独立客户端、越权操作、底牌隔离、重连、离桌接替、超时、房主转交、
全员准备与并发确认、踢人和 WIN 标记（含平局与边池）。

## 命令行版

使用已有的 `poker` Conda 环境（已验证 Python 3.14.7、PokerKit 0.7.5）：

```bash
conda activate poker
python play_poker.py
```

也可以不激活环境直接运行：

```bash
conda run --no-capture-output -n poker python play_poker.py
```

新建环境时安装依赖（需要 Python 3.11 或以上）：

```bash
conda create -n poker python=3.14 pip
conda activate poker
python -m pip install -r requirements.txt
```

## 操作

| 输入 | 含义 |
| --- | --- |
| `fold` / `f` | 弃牌 |
| `check` / `x` | 过牌；需要跟注时会拒绝，不会自动花费筹码 |
| `call` / `c` | 跟注提示的数额；无需跟注时请用 check |
| `raise 100` / `r 100` / `bet 100` | 本轮累计下注**加到 100**，不是额外增加 100 |
| `allin` / `all-in` / `a` | 合法时全下，支持筹码不足的全下跟注 |
| `q` / `quit` / `exit` | 退出 |

手牌结束后回车继续。Ctrl+C 或输入结束（EOF）也会正常退出。
未完成的手牌不会写入历史记录。
牌面显示为 `[A♠]`、`[10♥]` 等：♠ 黑桃、♥ 红桃、♦ 方块、♣ 梅花。
引擎与 JSONL 日志仍使用 `As`、`Th` 等原始记法。

## 字符牌桌与刷新

启动游戏即显示字符牌桌：你在下方，Bot-A 在左上，Bot-B 在右上，按顺时针排列。
座位固定，庄位/盲位逐手轮换；`BTN` 为庄家，`SB` 为小盲，`BB` 为大盲，
`>` 标出当前行动玩家。淘汰玩家保留原座位标记，避免双人阶段出现位置跳动。
桌面显示公共牌和底池，座位旁显示筹码、下注及弃牌/全下状态。
对手底牌用问号表示，结束后只展示实际亮出的牌。

终端中每次行动后自动清屏重绘，保留最近四次行动；机器人行动前短暂停顿，
方便跟上过程。手牌结果保留到按回车继续。需要查看连续输出时：

```bash
python play_poker.py --no-clear
```

输出重定向到文件、终端标记为 `dumb` 或执行 `--simulate` 时不会发送清屏控制符，
也不会等待机器人动画。建议使用支持 Unicode 的等宽字体和至少 80 列的终端。

## 已实现

- 自动发牌、下注轮推进、摊牌、全下、边池、平分底池和余筹码分配，由 PokerKit 处理。
- 永久玩家 ID 与每手位置分离，逐手轮换庄位和盲位。
- 零筹码玩家下一手退出；三人变双人时，下一位存活玩家接替上一手大盲。
- 双人桌庄家兼小盲，翻牌前先行动、翻牌后后行动。
- 真人淘汰时结束真人对战；机器人模拟继续到最终胜者。
- 当前下注轮、公共牌、自己的底牌、位置、筹码、下注、合法动作与总底池展示。
- 结算展示实际亮出的底牌、牌型、主池/边池分配、退回下注和每手净盈亏；不额外公开弃牌。
- 每次动作后检查筹码非负和总量守恒；自动推进有失败诊断与步数保护。
- 可复现洗牌、机器人随机决策和 JSONL 手牌记录。

CLI 默认三人桌；`Table` 接口接受 2 至 9 名玩家。三人及以上使用“移动庄家”规则，
跳过淘汰座位；尚未实现部分线下赛事使用的死庄规则、重新买入或升盲赛制。

## 机器人

```bash
python play_poker.py --list-bots
python play_poker.py --bots tight loose --seed 42
python play_poker.py --bots calling_station maniac --seed 42
python play_poker.py --bots nit equity --equity-samples 256 --seed 42
python play_poker.py --stack 200 --bots push_fold loose
python play_poker.py --stack 1000 --small-blind 5 --big-blind 10
```

| 策略参数 | 风格与行为 |
| --- | --- |
| `random` | 随机弃牌、跟注、过牌和最小加注，作为基线 |
| `tight` | 较紧，考虑起手牌、成牌/听牌、位置及跟注成本 |
| `loose` | 入池更宽，下注比 tight 更积极 |
| `nit` | 极紧，起手牌要求高，面对高成本跟注更加谨慎 |
| `calling_station` | 跟注站，偏爱过牌/跟注、不主动加注；弱牌遇大额下注会弃牌 |
| `maniac` | 狂野进攻，频繁下注/加注，翻牌前目标为 5 个大盲、翻牌后偏爱底池大小下注，包含弱牌诈唬 |
| `push_fold` | 剩余筹码加本轮已下注不超过 12 个大盲时，主要强牌全下、弱牌弃牌；可免费过牌时过牌；深筹码使用 tight |
| `equity` | 蒙特卡洛抽样未知牌，估计摊牌分池份额，结合跟注成本决定弃牌、跟注或价值下注 |

默认 Bot-A 使用 random，Bot-B 使用 tight。刷新后的牌桌顶部持续显示两个对手的策略。
`--bots` 和模拟中的 `--hero-bot` 均支持以上八种策略。
除 equity 外，策略的强度分数是启发式评分，不是胜率估计。
所有机器人只接收不可变的 `Observation`：自己的底牌、公共信息与合法动作，
不会收到完整引擎状态、对手底牌、牌堆或随机种子。

`equity` 默认每次估计抽样 128 次；`--equity-samples` 可以调整，次数越多越慢。
它会排除已知牌，补齐公共牌并给仍在牌局中的对手抽样底牌，全下对手仍参与比较，
平局按实际人数分摊。相同牌面与对手数量会复用最近一次估计。
抽样假设对手持有均匀随机底牌，尚未建模对手下注范围、弃牌收益或边池的精确 EV；
该策略用于入门对战，不保证比其他策略更强。

## 模拟、记录和测试

```bash
python play_poker.py --simulate 1000 --seed 42
python play_poker.py --simulate 1000 --hero-bot tight --bots random loose --seed 42
python play_poker.py --simulate 200 --hero-bot equity --bots nit maniac --equity-samples 64 --seed 42
python play_poker.py --seed 42 --history hands.jsonl
python -m unittest discover -s tests -v
```

模拟中座位 0 默认使用 loose；每场结束后重新开桌，直到完成指定手数。
输出累计净盈亏和完成场数。固定种子、参数、策略及动作序列可以复现结果。
JSONL 每行保存一手已完成牌局，包括本手洗牌种子、配置、位置顺序、初始筹码、
动作、策略、胜率抽样次数和结果；种子与初始状态可用于重建该手牌。历史包含复现所需的私有信息，
不属于传给机器人的公开观察数据。尚未提供独立的回放界面。

测试覆盖底池跨轮累计、非法输入不改变状态、弃牌结算、短筹码全下与加注重开、
边池、平局/奇数筹码、轮庄、三种位置的淘汰、双人行动顺序、盲注直接全下、
信息隔离、种子复现、日志复现、正常退出，以及 1000 手机器人对局。
额外覆盖八种策略的实际对局、短码加注限制、抽样排除已知牌、平局份额、
全下/弃牌玩家计数与蒙特卡洛随机种子复现。

## 全部机器人同桌比赛与筹码曲线

让当前注册的八种策略各占一个座位，持续对战到只剩一名玩家：

```bash
conda run --no-capture-output -n poker python tournament.py --seed 42
```

默认每人 2000 筹码、固定盲注 10/20、equity 抽样 128 次；不重新开桌、不补筹码、
不升盲、不设置固定手数截断。可使用 `--stack`、`--small-blind`、`--big-blind`、
`--equity-samples` 修改配置。`--output` 可指定一个新的输出目录，默认创建带时间戳的
`runs/all-bots-...` 目录；已有目录会被拒绝，避免混合不同比赛。

输出文件：

- `stacks.csv`：每手结算后的所有玩家筹码；第 0 行为初始筹码，淘汰后持续记 0。
- `hands.jsonl`：逐手配置、位置、发牌种子、动作和结算记录。
- `summary.json`：比赛状态、总手数、冠军、最终筹码、峰值、淘汰手数、名次及复现种子。

同手淘汰者并列，名次为该手结束时存活人数加一。固定盲注的比赛耗时不固定；
中断会保留已完成的手牌并标记为 `interrupted`，不能当作完整比赛结果。

绘图只依赖 Matplotlib，可在安装了它的环境中执行，不需要重新运行比赛：

```bash
python -m pip install -r requirements-plot.txt
python plot_tournament.py runs/你的比赛目录
```

生成 `chip-curves.png`、矢量图 `chip-curves.svg` 和分玩家视图 `chip-curves-by-bot.png`。
绘图前会检查记录连续性、筹码守恒及淘汰后筹码归零。图中采用阶梯曲线表示每手结算后的状态。

已完成示例保存在 `runs/all-bots-seed42/`：252 手结束，equity 获胜，最终 16000 筹码。
这是固定种子下的一场比赛，不代表策略的长期强弱排名。

## 代码结构

- `engine.py`：单手规则封装、观察与动作接口、牌桌和玩家身份管理。
- `bots.py`：八种机器人策略，仅返回动作，由引擎统一校验并执行。
- `play_poker.py`：命令行交互、模拟和历史记录。
- `terminal_ui.py`：花色符号、固定座位字符牌桌和终端清屏。
- `tournament.py`：全部策略同桌比赛、逐手筹码记录及排名。
- `plot_tournament.py`：验证比赛记录并绘制总览和各玩家曲线。
- `tests/test_poker.py`：固定牌局回归测试与模拟测试。
- `tests/test_strategies.py`：策略行为、胜率估计及多策略对局测试。
- `tests/test_tournament.py`：同桌比赛完整性、淘汰记录及整场复现测试。

后续可增加对手范围分析、策略参数配置、回放界面及网页界面。
