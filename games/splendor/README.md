# 璀璨宝石 · 局域网联机

一台电脑运行服务，2～4 个席位可由真人和 AI 混合组成，支持一人对战最多三位 AI。真人通过同一局域网内的浏览器加入。React + TypeScript 界面、Node.js + Socket.IO 服务端、SQLite 存档。运行时不依赖互联网；所有图标、脚本及二维码均在本地生成或加载。

## 启动

推荐 Node.js 24 LTS（最低 22.13）和 pnpm 11.19.0。

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

Linux / macOS 也可以直接运行：

```bash
./start.sh
```

脚本会在缺少依赖或构建产物时进行安装、构建，然后启动服务。此工作站未全局安装 Node 时，脚本也能使用 Codex 自带的运行环境。首次安装需要联网，之后可离线运行。

本机打开 `http://localhost:3000`。其他设备打开启动输出中的局域网地址，例如 `http://192.168.3.186:3000`，实际地址以启动输出为准。

1. 房主输入昵称、创建房间，点击分享链接与二维码。
2. 其他玩家打开分享链接，输入自己的昵称加入。
3. 也可以由房主点击“添加 AI 对手”补齐空位，AI 自动准备。所有真人点击“我准备好了”，房主点击“开始对局”。
4. 点击市场卡牌购买或预留；点击牌堆预留未知卡牌；在宝石银行选择拿取方式与颜色。
5. 达到 15 分后完成当前轮，系统结算；房主可以回到房间再来一局。

按 `Ctrl+C` 停止服务。下次在相同数据目录启动，玩家用原浏览器访问相同地址即可恢复座位。

```bash
# 自定义端口 / 数据目录
PORT=8080 DATA_DIR=./my-data ./start.sh

# 修改源码后重新构建并启动
./start.sh --rebuild

# 开发模式，前后端共享一个端口
./start.sh --dev
```

## 已实现

- 离线 AI 对手：房主可在等待房间添加、移除，支持单人练习及真人与 AI 混合对局。
- 原版实体卡牌照片：90 张卡面逐张匹配数值，本地按需加载；白、蓝、绿、红、黑实心色块统一用于资源和费用。小屏的市场可左右滑动，保留卡牌可读大小。

- 2 / 3 / 4 人基础版；90 张发展卡、10 位贵族；按人数配置资源。
- 拿不同色宝石、同色双拿、市场预留、盲预留、购买市场卡及预留卡。
- 永久折扣、自由选择黄金支付、免费购买、超出 10 枚后归还、多贵族选择。
- 最后轮结算、同分少卡获胜、共享胜利。
- 创建房间、准备、随机先手、邀请链接、二维码及多个网卡地址选择。
- 玩家私密手牌视图；服务端校验身份、回合、支付及动作参数。
- 操作去重、过期状态拒绝、自动重连、刷新恢复、服务器重启恢复。
- 房主离线后转移管理权；等待房间中可移除离线玩家。
- 对局记录（界面与快照保留最近 100 条）、查看公开产业、结束对局与再来一局。
- 适配桌面和小屏的布局、键盘操作、对话框及减少动画偏好。

## 联机与存档约定

- 服务默认监听 `0.0.0.0:3000`。房主浏览器也只是一个客户端；运行服务的电脑必须保持开启。
- 房间码定位牌桌，不是玩家身份。随机座位凭证保存在浏览器本地，数据库仅保存其哈希。
- 同一浏览器配置中的多个标签页共用座位。新标签页接管后，旧标签页停止操作。单机测试多人请使用不同浏览器或独立隐私会话。
- 普通断线保留座位。对局中不能直接移除玩家或跳过其回合；等待重连，或由房主明确结束本局。
- 对局快照、座位映射和已处理操作 ID 存在 `data/splendor.sqlite`，同一次有效操作在事务中提交后才确认成功。
- 备份时先停止服务，再复制整个 `data/` 目录（包括存在的 WAL 文件）。恢复时使用同一数据目录。
- 浏览器使用不同主机地址、端口或清除了站点数据时，不会自动取得原来的本地凭证。请固定主机地址与端口；当前版本不提供跨设备转移座位。
- AI 为本地启发式策略，无需 API Key。它考虑得分、贵族与资源需求，仅读取自己的可见视图，无法查看牌库顺序和他人的预留手牌。目前提供一个标准策略，不包含难度选择。
- AI 每次行动前短暂停顿；所有真人离线时暂停，真人恢复连接后继续。重启服务也可恢复待执行的 AI 回合。AI 不会成为房主，最后一位真人离开等待／结束房间时会清理该房间。
- 当前版本是单进程局域网服务，不包含公网账号、观战、扩展包或主机迁移。

## 连不上时

1. 其他设备要打开主机的局域网 IP，不能使用 `localhost`。
2. 确保连接的是同一网络，且路由器未开启访客网络隔离 / AP 隔离。
3. 确保系统防火墙允许所选端口的局域网入站访问。
4. 主机有 VPN、虚拟网卡时，分享面板可切换地址；选择 Wi-Fi 或有线网卡的地址。
5. 手机若暂停了后台页面，切回后等待自动恢复连接再操作。

## 开发与测试

```bash
pnpm dev          # 开发服务器，默认 3000
pnpm test         # 规则、完整对局模拟、真实 Socket.IO 客户端联机测试
pnpm build        # 类型检查、前端生产构建、服务端编译
pnpm check        # 测试与构建
node scripts/smoke.mjs  # 正式服务启动后的生产冒烟验证，测试房间自动清理
```

```text
src/
  engine/         # 纯规则引擎与基础版数值数据
  shared/         # 类型、费用计算、输入校验协议
  server/         # 房间、身份、Socket.IO、SQLite
  web/            # 中文界面与客户端连接恢复
tests/            # 规则、完整对局模拟与联机回归
docs/             # 数据来源、架构与验收说明
```

构建输出为 `dist/`（网页）与 `dist-server/`（服务端）。生产环境由 Node 同时提供页面与联机接口，不需要另起静态服务器。

规则依据、数据核对记录见 [docs/DATA_SOURCES.md](docs/DATA_SOURCES.md)，验证情况与人工验收步骤见 [docs/VALIDATION.md](docs/VALIDATION.md)。

本项目为非官方实现。卡面使用公开的原版实体卡牌照片，素材来源与对应关系见 [docs/ART_SOURCES.md](docs/ART_SOURCES.md)。Splendor 的名称及原游戏美术归其权利人所有；界面图标使用 Lucide。
