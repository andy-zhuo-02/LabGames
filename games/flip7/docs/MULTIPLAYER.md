# v0.2：局域网在线房间

## 一起玩

1. 一台电脑运行 `./games/flip7/start.sh`，保持服务运行。
2. 房主打开 `http://localhost:3007`，点击「局域网联机」，输入昵称，可勾选「开启记牌器」，然后创建房间。默认关闭。
3. 在房间中点击「邀请朋友」，将局域网邀请链接交给同一网络的朋友。朋友也可以打开同一个服务器的网页，在联机入口输入 6 位房间码。
4. 3～6 个席位可开局；支持全真人，也可由房主添加电脑补位。非房主真人点击「我准备好了」，全员在线并准备后由房主开始。每轮开场由玩家按座位顺序点击「翻开第一张」，开场特殊牌先处理，之后继续等待下一位翻牌。
5. 每轮结算后，任意未托管的真人可开启下一轮。整局结束后由房主点击「再来一局」，返回准备大厅，可调整记牌器后在原房间开新局。

朋友需使用服务器电脑的局域网地址，不能使用 `localhost`。邀请窗口列出服务器网卡地址；有多块网卡时选择共同网络对应的地址。两个人可以添加一位电脑组成三人局。页面继续使用原版卡面和现有印章效果。

## 行动限时与全桌提醒

- 每次开场翻牌、翻牌／收手、选择特殊牌目标都有独立的 10 秒倒计时；全桌显示同一截止时间，最后 3 秒变红。开场超时自动翻牌，即使之前已被三联翻发过牌；轮末的「下一轮」按钮不计时。
- 超时优先自动收手；没有可收手的牌时自动翻牌。特殊牌由电脑策略代选合法目标，只代操作本次，下一次仍可自己决定。
- 倒计时由服务器执行并保存。刷新、重连、切换大厅、房主操作或接管席位都不会延长当前截止时间。服务器也会拒绝截止时间之后到达的玩家动作，防止重复操作。
- 有人翻出「连翻三张」时，所有在线玩家立即看到带原版牌面的醒目提醒；选定目标后再次通知全桌。提示保留约 6 秒，不阻挡点击；连续翻牌中抽到的连翻三张也会提示。

- 任意玩家达成七连翻时，全桌显示七张牌展开、额外 +15 分和彩纸庆祝。三联翻导致的七连翻也会正确显示达成者；同次结算产生最终赢家时一并显示，重复同步不会重播。
- 庆祝不再自动消失：所有真人（包括达成者）都点击「为ta鼓掌」后才会共同收起。电脑自动鼓掌，面板实时显示人数与各席位状态，完成前禁止下一轮或再开一局。离线和托管的真人仍需重连确认；明确离开房间、转为电脑的席位自动完成。刷新、断线重连和服务器重启均保留进度。

## 全桌弹幕

- 大厅、牌桌和结算页底部可发送弹幕，支持自定义短句和三种快捷喊话；昵称由服务器提供。最多 40 个 Unicode 字符，每人每 2 秒一条。
- 消息在上方三条轨道飘过，不拦截卡牌点击；自己的弹幕为黄色。开启系统的减少动态效果时，改为短暂静态显示。
- 「弹幕：开／关」仅控制本机显示，偏好自动保存。切换关闭或离开页面会清空屏幕上的消息；刷新、重连不补播历史弹幕。
- 输入草稿不会被牌局同步覆盖，快捷喊话不会清空草稿。发送失败会提示并保留输入；弹幕不推进牌局版本，也不延长或重置行动计时。

## 记牌器

- 房主可在创建房间时选择，也可在准备大厅点击「开启记牌器」或「关闭记牌器」。整局结束后点击「再来一局」返回准备大厅即可调整，无需重新建房。每局进行中保持不变；大厅向全员显示设置，修改后其他真人需重新准备。
- 开启后在牌桌顶部点击「记牌器」展开或收起。每位玩家独立控制自己的面板，不影响其他人；查看时行动倒计时照常继续。
- 显示全部 22 种牌的「当前牌堆剩余 / 全套张数」。黄色表示自己的数字牌，零剩余会淡化；统计对全员相同，不显示牌堆顺序。
- 牌堆外包括桌面牌、弃牌与待处理的特殊牌。第二次机会被消耗、爆牌和连续翻牌都会正确计数。弃牌重新洗回时，统计相应更新，本轮桌面牌仍不计入牌堆；牌堆空时提示下一次翻牌将洗入弃牌。
- 房间设置和实时统计支持刷新、重连及服务器重启恢复；同一房间再开一局、房主接任时保留设置。旧房间默认关闭，关闭时服务器不发送记牌统计。

## 身份、离线与房主

- 房间身份保存在该浏览器、该访问地址的 `localStorage`。刷新或重新打开相同地址会自动恢复，不新增席位。改变主机地址、端口、浏览器或清理站点数据会失去原身份；昵称不能用于认领席位。
- 临时离开时直接关闭页面，席位保留；断线后自动重连。联机对局不会因为查看说明或切到后台而暂停。
- 只要还有真人在线，离线席位也按 10 秒限制自动代操作。离线满 30 秒后，房主可在房间大厅将其交给电脑；玩家回来后点击「接管我的席位」可恢复操作。
- 房主离线满 30 秒后，其他真人可以「接任房主」。房主明确离开时，房主身份按座位顺序交给下一位真人。
- 点击并确认「离开房间」会释放身份：大厅内移除席位，已开局时改为电脑，本局无法再以原身份加入。最后一位真人明确离开后房间关闭。
- 所有真人离线时暂停自动操作，任意真人回来后继续；若原截止时间已过，立即处理那一次超时，再给下一次决定完整的 10 秒。大厅中房主可移除电脑或离线席位。

## 协议与状态

`src/rooms.js` 统一运行规则和电脑，服务端持有完整牌局。浏览器通过同源 JSON HTTP 请求发出操作，通过带身份认证的 SSE 流接收全量公开快照和在线状态。没有第三方网络依赖。

| 请求                             | 用途                                   |
| -------------------------------- | -------------------------------------- |
| `POST /api/rooms`                | 创建房间，返回房间码、席位令牌和快照   |
| `POST /api/rooms/:code/join`     | 加入尚未开始的房间                     |
| `GET /api/rooms/:code`           | 获取自己的公开快照                     |
| `GET /api/rooms/:code/events`    | SSE 订阅，10 秒心跳                    |
| `POST /api/rooms/:code/danmaku`  | 发送弹幕，包含 `requestId` 与 `text`   |
| `POST /api/rooms/:code/commands` | 准备、电脑管理、开局、游戏动作、托管等 |
| `GET /api/network`               | 局域网邀请地址                         |

除创建、加入和地址发现外，房间接口使用 `Authorization: Bearer <token>`；令牌不放在邀请链接或 SSE URL 中。服务端仅存 SHA-256 哈希。该实现用于可信局域网，默认是 HTTP，没有公网账号系统或 TLS。

操作包含 `requestId`、`expectedRevision`、`command`。所有房间变更和电脑操作串行提交，先写存档，再广播结果。服务器检查身份、房主权限、当前行动者、特殊牌目标和状态版本。每个房间保存最近 512 次真人操作编号及内容，用同一编号重试不会重复翻牌；不同编号的过期操作返回 409，客户端刷新状态后提示重新操作。传输失败自动重试一次，保留原编号和版本。

鼓掌操作为 `{ type: "applaud", applauseId }`，只确认发送者自己的席位。该操作允许版本滞后，便于全员同时点击；必须匹配本次庆祝的唯一编号，旧庆祝请求会被拒绝。快照的 `applause` 包含庆祝编号、达成者、轮数、参与者鼓掌状态和 `complete`，未完成时服务器也会阻止下一轮和再开一局。已完成回执保留到换轮或返回大厅，避免刷新后再次弹出。

快照还包含 `serverNow`、`turnClock` 和短期 `notices`；客户端用服务器时间校准显示，通知通过结构化牌桌事件生成，避免连锁翻牌漏报。公开牌局调用 `publicView()`，不含牌堆顺序、弃牌内容、随机数状态、内部任务队列或令牌哈希。连接使用 25 秒无数据超时，失败后每 1.5 秒尝试重连；连接恢复时直接接收完整快照。

创建请求支持布尔值 `cardTracker`，省略时为 `false`。房主可在准备大厅发送 `{ type: "setCardTracker", cardTracker: boolean }` 调整；实际变更会取消其他真人的准备状态。进行中的对局（包括轮末结算）和未返回准备大厅的整局结算禁止修改。变更按正常版本检查、去重、持久化和 SSE 广播流程提交。快照的 `settings.cardTracker` 表示房间设置；只有开启且已开局时，`cardTracker` 才包含总剩余量、牌堆外数量和按固定牌型排序的剩余统计，否则为 `null`。统计由 `src/card-tracker.js` 生成，不依赖截断的动态日志，不改变电脑策略使用的 `publicView()`。

弹幕使用独立 SSE 事件：新客户端通过 `events?danmaku=1` 订阅 `event: danmaku`，旧客户端仍只收到牌局快照。弹幕不写入存档；服务端在内存中保留最多 60 秒的请求回执用于重试去重，发送者身份和房间范围均经校验。离开的席位不能继续收发。

## 持久化

默认写入 `games/flip7/data/rooms.json`，临时文件写完后原子重命名；该目录已被 Git 忽略。可设置 `FLIP7_DATA_FILE=/绝对路径/rooms.json`。同一存档文件只能由一个服务器进程使用；多个实例应分别指定文件。

重启服务后保留牌局、席位和去重记录，所有真人先视为离线，连接后恢复。启动时忽略最后一次牌局／大厅变更超过 7 天的房间；上限 100 个房间。无法读取或损坏的存档会阻止启动并报告错误，不会自动覆盖。

单人存档仍在原来的浏览器存储键下，与联机房间分开；加入或退出联机房间不会覆盖单人进度。

## 验证

`./games/flip7/start.sh --test` 包含规则、300 局单人模拟、4 局完整多人规则模拟，以及以下房间和 HTTP/SSE 测试：

- 3 客户端推送一致、刷新所需的身份与快照恢复、在线／离线通知。
- 房主权限、准备条件、容量、身份校验、非法和越序动作、特殊牌目标。
- 并发冲突、重复请求去重、服务器重启后的幂等重试。
- 七连翻鼓掌门槛、并发确认、过期庆祝请求、HTTP/SSE 全桌同步、刷新／重启后部分及全部进度恢复、离线和托管席位、三联翻达成者与最终赢家不同时的庆祝。
- 多标签页在线状态、离线房主接任、电脑托管、重返接管、所有真人离线暂停。
- 完整牌局中的计分与 94 张牌守恒；单人和多人存档校验隔离。
- 10 秒边界、过期请求与定时器竞争、重连不重置、特殊牌重新计时、连翻三张全员提醒及嵌套翻牌提醒。
- 持久化失败回滚、损坏存档拒绝、私有文件不可访问、跨站和超限请求拒绝。
- 记牌器默认关闭、创建与修改参数校验、非房主不能修改、修改后重新准备、局内禁止调整、原房间局后开关与新局生效、加入者不能覆盖房间设置、HTTP/SSE 同步、22 种牌统计、第二次机会、特殊牌待处理、洗牌时排除桌面牌、旧存档兼容和重启／再开一局／房主变更后的设置保留。
